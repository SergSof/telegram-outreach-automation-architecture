# Решение тестового задания

## Автоматизация Telegram-аутрич-процесса

## 1. Цель решения

Сейчас основной канал лидогенерации — Telegram. Каждый день используется около 300 аккаунтов, через которые отправляется 3000–5000 персонализированных сообщений. База хранится в Google Sheets, менеджер вручную берет пул лидов, загружает его в сервис рассылки, затем вручную обрабатывает ответы и передает готовых лидов в отдел продаж. Сделки в AmoCRM также создаются вручную. Главные проблемы: процесс не масштабируется, горячие лиды остывают из-за задержки реакции, нет прозрачной аналитики по сегментам, текстам и конверсиям. 

Цель архитектуры — перевести процесс из ручной таблицы и ручной обработки ответов в управляемую систему, где каждый лид имеет статус, историю касаний, сегмент, отправленный текст, ответ, квалификацию и следующее действие.

---

## 2. Целевая архитектура процесса

```text
Google Sheets / исходная база
        ↓
Импорт и нормализация данных
        ↓
PostgreSQL — единая база лидов и событий
        ↓
Сегментация и приоритизация
        ↓
Генерация персонализированного сообщения
        ↓
CRMChat — Telegram outreach и обработка ответов
        ↓
Ответ лида в Telegram
        ↓
AI-классификация ответа
        ↓
AmoCRM / задача менеджеру / follow-up / отказ
        ↓
Аналитика по сегментам, текстам, аккаунтам и сделкам
```

Главная идея: **таблица остается источником импорта, но не центром управления процессом**. Центром должна стать база лидов и событий, где фиксируется вся история: импорт, валидация, отправка сообщения, ответ, квалификация, создание сделки, отказ или повторное касание.

## 3. Роль CRMChat

[CRMChat](https://crmchat.ai/ru/telegram-outreach?utm_source=chatgpt.com) используется как слой Telegram-аутрича: отправка сообщений, работа с большим количеством Telegram-аккаунтов, планирование кампаний, персонализация сообщений, единый inbox для ответов и управление ответами с разных аккаунтов. На официальной странице Telegram Outreach у CRMChat указаны персонализация через поля, планирование сообщений, работа с несколькими аккаунтами, дневные лимиты, автоматические последовательности, аналитика и AI-агенты для ответов. ([CRMChat][1])

При этом CRMChat не должен быть единственным источником правды. Его роль — **операционный слой Telegram-коммуникации**. Основной учет лидов, статусов, событий, аналитики и связи с продажами лучше вести в собственной базе данных.

```text
CRMChat = отправка, Telegram-аккаунты, inbox, ответы
PostgreSQL = лиды, статусы, события, история, аналитика
n8n / backend = логика автоматизации и интеграции
AmoCRM = финальная CRM для отдела продаж
```

## 4. Работа с базой лидов

В примере базы есть данные, которые уже подходят для персонализации и сегментации: продавец, ОГРН, продажи, выручка, средняя цена, сегмент, ИНН, краткое наименование, ФИО руководителя, ссылка на Ozon, Telegram, ссылка на товар, Sellerstats и категории товаров. 

После импорта система должна проверять качество данных:

```text
- есть ли Telegram;
- не пустое ли название продавца;
- есть ли ИНН / ОГРН;
- нет ли дубля по Telegram;
- нет ли дубля по ИНН / ОГРН;
- не находится ли контакт в blacklist;
- не было ли уже касания по этому лиду;
- заполнены ли ключевые поля для персонализации.
```

Пример статусов лида:

```text
new
validated
ready_for_outreach
in_sequence
replied
qualified
sent_to_sales
deal_created
lost
do_not_contact
error
```

Это нужно, чтобы не отправлять повторные сообщения одному и тому же продавцу, не терять ответы и видеть, на каком этапе находится каждый лид.

## 5. Основной процесс: от базы до сделки

### 5.1. Импорт и подготовка

База остается в [Google Sheets](https://www.google.com/sheets/about/?utm_source=chatgpt.com) или загружается из CSV/Excel. Дальше [n8n](https://n8n.io/?utm_source=chatgpt.com) по расписанию забирает новые строки, нормализует данные и сохраняет лидов в [PostgreSQL](https://www.postgresql.org/?utm_source=chatgpt.com).

На этом этапе выполняются:

```text
- очистка полей;
- дедупликация;
- проверка Telegram;
- проверка ИНН / ОГРН;
- присвоение статуса;
- запись источника лида;
- подготовка данных для персонализации.
```

### 5.2. Сегментация и приоритизация

Лиды делятся на группы по данным из базы:

```text
- выручка;
- количество продаж;
- сегмент A / B / C;
- категория товара;
- юртип: ИП / ООО;
- наличие ФИО руководителя;
- качество Telegram-контакта.
```

Пример логики:

| Условие                                                | Приоритет     |
| ------------------------------------------------------ | ------------- |
| высокая выручка + много продаж + есть ФИО руководителя | высокий       |
| средняя выручка + понятная категория + есть Telegram   | средний       |
| неполные данные / слабая выручка                       | низкий        |
| дубль / blacklist / отказ ранее                        | не отправлять |

### 5.3. Генерация сообщения

Для MVP лучше использовать не свободную генерацию через LLM, а шаблоны с переменными. Это надежнее и проще контролировать.

Пример шаблона:

```text
Здравствуйте, {{director_name}}.

Вижу, что {{seller_name}} продает на Ozon в категории {{category}}.
По открытым данным у вас около {{revenue}} ₽ выручки и {{sales_count}} продаж.

Хотел коротко предложить решение, которое помогает продавцам увеличить продажи. Актуально обсудить?
```

Правила:

```text
- использовать только факты из базы;
- не выдумывать цифры;
- не обещать результат, которого нет в оффере;
- сохранять template_id и версию текста;
- фиксировать, какой текст был отправлен какому лиду.
```

LLM можно подключить позже — не для полной свободы, а для аккуратной адаптации текста под категорию, сегмент и контекст.

### 5.4. Отправка через CRMChat

После подготовки сообщение попадает в очередь отправки и передается в [CRMChat](https://crmchat.ai/ru/telegram-outreach?utm_source=chatgpt.com).

Очередь должна отвечать на вопросы:

```text
- кому отправить;
- с какого Telegram-аккаунта отправить;
- когда отправить;
- какой шаблон использовать;
- не превышены ли лимиты;
- был ли уже ответ;
- нужно ли остановить follow-up.
```

Пример структуры очереди:

```text
outreach_queue
- id
- lead_id
- crmchat_account_id
- template_id
- message_text
- scheduled_at
- sent_at
- status
- error_message
```

Статусы очереди:

```text
pending
scheduled
sent
failed
replied
cancelled
```

### 5.5. Обработка ответа

Когда лид отвечает в Telegram, ответ фиксируется в CRMChat и передается обратно в систему через webhook или периодический опрос API.

Дальше ответ сохраняется в PostgreSQL и классифицируется через AI.

Классы ответов:

| Тип ответа                | Действие                             |
| ------------------------- | ------------------------------------ |
| заинтересован             | создать сделку в AmoCRM              |
| хочет подробности         | создать сделку + уведомить менеджера |
| вопрос по цене / условиям | создать задачу менеджеру             |
| напишите позже            | поставить follow-up                  |
| не интересно              | закрыть лид                          |
| негатив / не писать       | добавить в do_not_contact            |
| непонятный ответ          | отправить на ручную проверку         |

Пример результата AI-классификации:

```json
{
  "lead_status": "hot",
  "intent": "wants_details",
  "summary": "Лид заинтересован, просит подробности",
  "next_action": "create_deal",
  "urgency": "high"
}
```

AI не заменяет менеджера полностью. Его задача — быстро отделить горячие и теплые ответы от отказов, негатива и непонятных сообщений.

### 5.6. Создание сделки в AmoCRM

Если лид квалифицирован как горячий или теплый, система автоматически создает сделку в [AmoCRM](https://www.amocrm.ru/?utm_source=chatgpt.com).

В сделку передается:

```text
- название продавца;
- ФИО руководителя;
- Telegram;
- ИНН / ОГРН;
- платформа;
- категория;
- выручка;
- продажи;
- сегмент;
- ссылка на продавца;
- ссылка на товар;
- текст первого сообщения;
- ответ лида;
- AI-резюме;
- источник: Telegram outreach / CRMChat.
```

Пример названия сделки:

```text
Sweet City / Ozon / Продукты питания / Telegram outreach
```

Пример комментария в сделке:

```text
Лид ответил положительно и просит подробности.

Продавец: Sweet City
Выручка по базе: 1 644 739 ₽
Продажи: 2860 шт.
Сегмент: B
Категория: продукты питания

Рекомендуемое действие: связаться в течение 5–10 минут.
```

После создания сделки менеджер получает уведомление в AmoCRM и/или Telegram-группу sales-команды.

## 7. Узкие места и решения

### Узкое место 1. Ручная обработка ответов

Сейчас менеджеры сами читают ответы, квалифицируют лидов и передают их в продажи. При объеме 3000–5000 сообщений в день это становится бутылочным горлышком. 

**Решение:** все входящие ответы автоматически сохраняются, классифицируются через AI и получают следующее действие: создать сделку, поставить follow-up, закрыть лид, добавить в blacklist или отправить на ручную проверку.

### Узкое место 2. Задержка передачи в продажи

В текущем процессе отдел продаж может выйти на связь через 3–4 часа. За это время горячий лид может остыть. 

**Решение:** при положительном ответе сделка создается автоматически, менеджер получает уведомление сразу. Для горячих лидов вводится SLA реакции — например, 5–10 минут.

### Узкое место 3. Нет аналитики по сегментам и текстам

Сейчас нет понимания, какие сегменты и какие тексты работают. 

**Решение:** каждое действие сохраняется как событие: импорт, валидация, отправка, ответ, классификация, сделка, закрытие. Это позволяет строить аналитику по сегментам, категориям, шаблонам сообщений, Telegram-аккаунтам и менеджерам.

## 8. Этапы внедрения

### Этап 1. MVP

```text
- импорт базы из Google Sheets;
- сохранение лидов в PostgreSQL;
- дедупликация и проверка качества данных;
- генерация сообщений по шаблонам;
- передача сообщений в CRMChat;
- получение ответов из CRMChat;
- AI-классификация ответов;
- автоматическое создание сделок в AmoCRM;
- уведомление менеджеров;
- базовая аналитика по отправкам, ответам и сделкам.
```

### Этап 2. Улучшение качества

```text
- A/B тесты текстов;
- разные follow-up цепочки по сегментам;
- улучшение AI-классификации;
- контроль SLA менеджеров;
- blacklist / do_not_contact;
- аналитика по Telegram-аккаунтам;
- отчеты по сегментам, категориям и шаблонам.
```

### Этап 3. Масштабирование

```text
- отдельный backend на Python / FastAPI для сложной бизнес-логики;
- очередь задач для стабильной обработки больших объемов;
- retry-механизмы при ошибках отправки;
- мониторинг состояния Telegram-аккаунтов;
- скоринг лидов;
- прогнозирование качества сегментов;
- расширенная BI-аналитика.
```

## 9. Финальная формулировка

Предлагаемая архитектура переводит Telegram-аутрич из ручного процесса в событийную систему. Google Sheets остается источником базы, CRMChat используется для Telegram-рассылки и обработки ответов, PostgreSQL хранит лидов, статусы и события, AI быстро квалифицирует ответы, а AmoCRM используется для дальнейшей работы отдела продаж.

Такое решение закрывает основные проблемы текущего процесса:

```text
- убирает ручную передачу лидов;
- сокращает задержку реакции на горячие ответы;
- снижает риск повторных касаний и дублей;
- дает прозрачную аналитику по сегментам, текстам и аккаунтам;
- позволяет масштабировать процесс без пропорционального роста нагрузки на менеджеров.
```

Главная логика решения: **не просто автоматизировать рассылку, а построить управляемую воронку Telegram-аутрича — от базы до сделки и аналитики результата.**
